# AGENTS.md

## Project

Учебная конфигурация 1С `БиблиотекаСтандартныхПодсистемДемо` на БСП `3.1.5.473`. Источник истины — XML-выгрузка: `src/cf` (основная конфигурация) и `src/cfe` (расширения). `var/` — только локальная среда выполнения.

Платформа проекта — `8.3.27.1936`; режим совместимости — `8.3.14`. Выгрузка имеет формат XML `2.20`, поэтому не переключайтесь на другую платформу без повторной выгрузки.

`../edu` — отдельный проект. Его можно читать как справку по проверенным командам 1С, но нельзя изменять, копировать целиком или считать частью этого репозитория.

## Credentials

В шаблоне есть пользователь `Администратор` с пустым паролем. Скрипты используют его по умолчанию; переопределение — `-UserName` или `ONEC_USER`.

## Commands

Запускать из корня репозитория. Если `.ps1` заблокированы:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

- Восстановить шаблон в `var/ib` (создаёт ИБ, если её нет): `./tools/restore-infobase.ps1`
- Выгрузить конфигурацию в `src/cf`: `./tools/dump-config.ps1`
- Загрузить `src/cf` в `var/ib`: `./tools/load-config.ps1`
- Обновить конфигурацию БД: `./tools/update-db.ps1`
- Проверить конфигурацию: `./tools/check-config.ps1`
- Сделать резервную копию: `./tools/backup-infobase.ps1`

Все скрипты принимают `-OneCExecutable`, `-InfoBasePath`, `-UserName`, `-Password`; переменные окружения: `ONEC_EXE`, `ONEC_INFOBASE_PATH`, `ONEC_USER`, `ONEC_PASSWORD`. Без `-OneCExecutable` выбирается самый новый установленный `1cv8.exe`.

## Rules

- Тестирование проводит только пользователь. Ассистент не создаёт тесты и автоматические тестовые сценарии и не запускает тесты или проверки конфигурации. Команды проверки в этом документе приведены для пользователя.
- Реализация должна быть максимально простой: только необходимое для текущей задачи, без лишних абстракций, зависимостей и функциональности на будущее.
- Git в процессе разработки не используется. Ассистент не выполняет команды Git, не создаёт коммиты, ветки или рабочие деревья.
- Эти правила процесса имеют приоритет над прежними планами и описаниями проверок в документации проекта.
- `src/cf` — это ~10 400 файлов и ~207 МБ; не применять к нему массовое форматирование.
- Не создавать отдельную или копию ИБ для проверок без явной просьбы. Работать с `var/ib`.
- Не делать резервные копии перед применением изменений в информационных базах, включая обновление конфигурации БД и реструктуризацию. Создавать резервную копию только по явной просьбе пользователя.
- После изменений в `src/cf` или `src/cfe` сообщать пользователю, что изменения готовы к ручному тестированию; проверку конфигурации пользователь запускает самостоятельно.
- `./tools/check-config.ps1` по умолчанию не проверяет incorrect references. С `-IncorrectReferences` видны два известных замечания в справке демо-БСП; не исправляйте их изменением поставляемых объектов без необходимости.
- Не изменять поставляемые объекты БСП без необходимости; прикладной код держать в расширениях, пока не определены собственная подсистема и префикс проекта.
